# 官方 SimulationCraft 包兼容性验证

验证日期：2026-10-27，Asia/Shanghai。

## 结论

官方 Windows 命令行包能够承担 WoWGearMatrix 的大部分数值计算，但本次验证的包不能完整替换当前适配器。替换需要重新实现输入组织、报告解析、元数据补全和异常隔离；神圣圣骑士、织雾武僧的属性快照仍有明确缺口。

自行编译不是调用 SimC 的必要条件。当前自行编译的价值是直接访问内部属性、倍率和装备数据库，并绕过与纯属性查询无关的战斗验证。官方 CLI 可以作为替代方案继续开发，但本次结果不支持直接删除现有适配器。

本次仅新增验证记录；应用继续使用现有 WASM 引擎。

## 功能对照

| 功能 | 实测结果 | 替换时需要处理的内容 |
| --- | --- | --- |
| 装备装等、主属性、副属性、额外属性 | 样例中 25 件有效装备全部一致；另 1 行是界面本来就跳过的衬衫 | 混合主属性字段需按专精转换，护甲需额外提取 |
| 背包候选与同槽位多件装备 | 原始注释不会进入官方的身上装备报告；组织为 26 个独立角色后，批处理成功 | 在应用中解析背包注释，保留来源和重复候选，生成独立计算配置 |
| 同 ID、不同 bonus | 测试戒指从装等 321 正确变为 311 | 保留完整物品参数，不能只按物品 ID 缓存 |
| 无装备基础属性 | 40 个专精中 38 个输出有效结果并在已比较字段中一致 | 部分职业需提供零属性虚拟武器或盾牌，避开战斗武器验证 |
| 神圣圣骑士、织雾武僧 | 单独运行退出码 40，提示当前不支持；开启实验专精及改角色定位仍失败 | 加入辅助角色虽能生成 JSON，但这两个专精的属性快照为空，不能当作已支持 |
| 属性天赋开关 | 184 组配置中 174 组已比较字段一致 | 6 组受上述两个专精限制，另 4 组武僧英雄天赋单独启用被完整树校验拒绝 |
| 种族 | 26 个种族中 25 个在已比较字段中一致 | 土灵在正式模拟的角色激活阶段自动获得 110 暴击；现有适配器的裸装状态不包含该效果 |
| 姿态、形态 | 9 组状态对照一致 | 用自定义战斗前动作设置姿态/形态，再执行属性快照；不能使用默认动作列表 |
| 护甲与主属性、精通联动 | 20 组探针均可计算，按项目取整规则与当前结果相符 | 原始护甲存在 5 处小于 0.2 的差值，来源是项目按整数舍入新增护甲，官方报告保留小数 |
| 法术基值、精通信息 | `spell_query` 及其 XML 输出可查询 | 基值与实际点数效果不同，例如莱卡拉基值为 3，2 点结果为 6；仍需解析点数和效果修正 |
| 空插孔、套装 ID、美化唯一分类 | 标准装备 JSON 未直接输出 | 需要补充数据库元数据；`show_bonus_ids=1` 没有列出仅含唯一分类的 bonus `8960` |
| 中文名称 | 可继续使用现有本地 JSON 词库 | 按物品 ID 查询，保留导出文本名称及官方英文名称回退 |
| 搜索、筛选、自定义装备、标签、导出及保存 | 实现位于项目 JS 层，没有必须使用 WASM 的要求 | 此次未把官方 CLI 接入 Electron，因此没有宣称这些功能完成了原生后端的界面验收 |

专精、种族、天赋的比较范围：裸装主属性、耐力、护甲及评级，以及暴击、急速、精通、全能、闪避、吸血百分比。数值容差为 0.005。加速百分比、原始属性、倍率和元数据单独验证，不包含在上述通过计数中。

天赋用例的 ID、点数和所属树来自项目当前目录及固定源码，期望值来自现有 WASM。这验证了官方程序能否计算已知配置，不等于官方包已经能独立生成项目的完整天赋目录。

## 实际调用方式

计算裸装属性时显式关闭消耗品和团队增益，并覆盖默认动作列表。例如：

```ini
strict_parsing=1
iterations=1
threads=1
max_time=1
fixed_time=1
vary_combat_length=0
optimal_raid=0
item_db_source=local
allow_experimental_specializations=1

warrior="Audit"
level=90
race=human
spec=arms
flask=disabled
food=disabled
potion=disabled
augmentation=disabled
temporary_enchant=disabled
actions.precombat=snapshot_stats
actions=wait,sec=1
json2=result.json
```

用官方 `simc.exe input.simc` 运行。所需快照位于 `sim.players[].collected_data.buffed_stats`，逐件装备的常见属性位于 `sim.players[].gear`。

官方命令行角色名使用 `deathknight`、`demonhunter`，需要转换项目内部的 `death_knight`、`demon_hunter`。默认宽松解析可能把未知指令忽略后仍返回 0；适配器应同时检查退出码、报告存在性及有效属性。

缺少武器的职业使用无属性虚拟武器后可以输出基础属性。例如死亡骑士使用 `main_hand=probe,weapon=sword2h_3.0speed_1min_1max`。这种办法不能解决官方直接拒绝的两个治疗专精。

背包装备可组织为不同角色，配合 `single_actor_batch=1` 一次计算。本次 26 个角色的批处理约 329 ms；这是本机单次测试，不是稳定性能承诺。

## 明确的适配缺口

1. **原始属性和倍率没有现成的等价 JSON 接口。** 官方快照给出最终属性；项目还需要种族/职业原始属性、装备倍率、天赋开关差值及联动响应。部分数据可以用多次受控探针推导，不能只换一个解析器就得到全部内容。
2. **装备 JSON 缺少部分元数据。** `gear` 提供装等、名称、装备编码和评级，但没有直接提供护甲、空插孔数量、物品套装 ID、美化的唯一装备分类。单件受控配置可以恢复护甲；其余项目需要继续补数据。
3. **无战斗裸装状态与模拟激活后的快照有差别。** 土灵默认矿物效果就是实际例子。`override.precombat_state` 设为 0 仍出现 110 暴击；尝试取消该 buff 返回“cannot be cancelled”。不能把所有官方快照都直接当成现有裸装状态。
4. **武僧英雄天赋的单项开关存在校验限制。** 酒仙、踏风的 `Veteran's Eye`、`Against All Odds` 共 4 组配置触发“Found 1 talents, expected 13”。尝试完整树加零点占位后，未得到与现有行为一致的结果。完整合法天赋构筑能否用于差分重建，需要另行设计验证。
5. **错误处理不同。** 未知物品会使整个人物初始化失败；未知 bonus `999999999` 却被静默接受，测试头盔退回装等 48。当前适配器会明确报错，并让其他有效物品继续完成。替换时需要自行补上相同校验及逐件隔离。
6. **输入仍要严格组织。** 专门测试的 `source=wowhead` 能覆盖全局 `item_db_source=local` 并尝试联网。当前应用的参数白名单和受限导入范围需要保留。

## 另外发现的现有公式差异

这些问题在保持当前后端时也存在，不能归为“切换官方包造成的新问题”。本次没有修改应用公式。

### 加速贡献相差 10 倍

用无天赋、无消耗品的人类武器战提供 1000 加速等级，读取官方最终加速等级仍为 1000。无额外移速效果时，官方 `speed_pct` 实际存储移动速度，可用其相对基础速度 7 的增量得到评级贡献。

| 等级 | 当前 `rating.js` 评级贡献 | 官方计算的评级贡献 |
| --- | --- | --- |
| 1 | 36.30009281% | 3.63000928% |
| 80 | 36.30009281% | 3.63000928% |
| 90 | 32.43458645% | 3.24345864% |

项目随附 SimC 源码的 `player_t::composite_run_speed()` 含额外的 `0.1` 系数，当前 JS 的加速贡献计算没有应用该系数。官方 JSON 的 `speed_pct` 则使用包含基础移速的 `composite_movement_speed()`，也不能直接当作百分比读取。例如裸装人类是 7，暗夜精灵是 7.14，猫形态可以是 9.24。

### 低等级精通规则不同

1 级、1020 最终精通等级的探针中，官方精通百分比为 0，当前 JS 换算为 138.6%。80、90 级的精通对照一致。需要单独核查低等级精通解锁规则，不能用这三个等级的抽样宣称已完成全部 1–90 级验收。

## 建议

当前优先保留现有适配器。官方包很适合用于数值交叉验证，也已经证明可以承担装备解析和大部分专精的属性计算。

如果目标是以后完全不用编译 SimC，需要先补齐两个治疗专精的属性路径、天赋单项开关、原始属性/倍率导出、装备元数据及错误校验；这会把维护工作转到 JS 适配器和补充数据表。现阶段没有证据表明这条路线能以更少的维护成本覆盖所有现有功能。

## 复核方法与边界

原始输入、官方 JSON、stdout/stderr、WASM 对照结果及验证脚本保存在 `.tmp/official-simc-20261027/`，并归档到上方证据包。证据包不含官方 EXE 或 121 MB 的原始下载包；它们仍保留在同一工作目录，来源及哈希见上文。

主要结果：`matrix-results.json`、`item-results.json`、`attribute-results.json`、`summary.json`。脚本和采样结果都能从证据包复核。原生用例可以直接以记录的 `runs/<用例>/input.simc` 再次启动官方程序。

没有切换生产后端，没有构建使用官方 CLI 的 Electron 发布包，也没有执行游戏内截图/面板验收。搜索、保存及 UI 的现有测试未因这次只新增验证记录而重新运行。
